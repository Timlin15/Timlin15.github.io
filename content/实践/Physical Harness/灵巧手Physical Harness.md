在 Physical harness 领域上周调研了三篇工作：[RPent](https://github.com/RLinf/RPent)、[PyRUA](https://dagroup-pku.github.io/PyRUA-Lean/)、[RoboDoctor](https://arxiv.org/pdf/2610.35604v1)。三者都是基于夹爪泛化的 harness 框架。其中比较侧重上层 VLM（astra）和下层 VLA 的架构设计。

## RPent
RPent 这篇工作比较强调「动作原语」，即指**构成复杂操作任务的最基本、不可再分的原子级动作单元**，比如「move to」、「grab」这类原子动作。

其核心思路是将大模型作为大脑，通过 MCP 一次调用一个工具，看结果后再决定下一步。
- 感知：`segment` 用 SAM 3 分割物体，`back_project` 结合深度和相机内外参算出物体的 3D 坐标。
- 运动：`move_to(xyz)` 用 CuRobo 求 IK，是经典规划，不是 VLA。
- VLA 的作用：只用于 `pi0_pick` 这一个抓取技能。规划器先把手臂摆到物体附近，再交给 VLA 完成接触；抓没抓住由"抬升 + 夹爪闭合"来判断。

## PyRUA
相较RPent，这个工作是 llm 通过写一段 Python，来操作 `robo` 对象。其在 python 中调用的感知和VLA 模块是部分复用 RPent 的动作原语，并且可选 VLA 和 VLM 都不作用。是一种「Code as policy」方法

## RoboDoctor
VLA 每预测一个动作块，大模型先诊断，然后要么放行这个动作块的一段前缀，要么施加有界的纠正。


其中如果想迁移到当下的工作中，可尝试的方向有：1. 灵巧手 2.触觉
后者相对好验证，可以查看 llm 是否比 VLA 更擅长接受触觉信息，比较成功率即可。前者相对比较难设计。
